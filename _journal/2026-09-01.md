# 2026-09-01

## Small-screen defaults (from SPE) — Part 1 of `_doc/2026-09-01-small-screen-defaults-and-laradcs-sync.md`

Decision (Mark): the layout values the SPE tutorial fork proved on a 1024-CSS-px
viewport at 4K become DCS defaults, not a preset. dcs.spa already had the fluid
`--text-*` tokens, the pre-paint `<head>` script and narrow/wide mode, so three
things changed.

### Pin breakpoint 1280 → 960
- `base.css` `@media (min-width: 960px)` for `.pin-toggle`, `.pinned` transforms,
  `body.*-pinned main` margins, `.grid-3`.
- `base.js` `restore()` (`innerWidth >= 960`) and the `matchMedia` listener.
- `site.css` content-width `@media` (the narrow/normal/wide cap) moved to 960 too.

### Width model: `clamp(200px, <pct>, 100%)`, default 15%
- `--sidebar-width-left/right: 15%`; `--sw-l/--sw-r: clamp(200px, …, 100%)`.
  1024 → 200 / 624 / 200. 1280 → still 200 each (15% = 192, floor wins). The
  percentage stays user-adjustable 10–100%; SPE's 300px cap deliberately not
  adopted — it would make drag-to-100% unreachable.
- Spinner `value` attributes in `index.html` → 15.

### Geometry: fixed full-width topnav, sidebars beneath it
- `.topnav { position: fixed; inset 0 x; z-index: var(--z-fixed) }`;
  `main { margin-block-start: var(--topnav-height) }`;
  `.topnav + .container` offset likewise.
- `.sidebar { top: var(--topnav-height); height: calc(100vh - var(--topnav-height)) }`.
- Deleted: `body.*-pinned .topnav` push rules, the 3.75rem carousel-header padding
  reserve for the hamburger, the `::after` rail `top` animation + `body.scrolled`
  toggle and its scroll listener. New token `--sidebar-header-height: 3rem` (the
  header no longer has to match the topnav).

### REVERTED the same day: geometry (the section above)
Mark caught it as a regression: the sidebar controls must sit level with the hamburgers
in a three-column top row, and the centre topnav must scroll away with the content while
the two sidebar headers stay fixed. That is foundational DCS, not a "small-screen value";
SPE's fixed full-width topnav is SPE's own simplification. Restored exactly:
`.topnav { position: relative; transition: margin }`, `.sidebar { top: 0; height: 100vh }`,
`.carousel-header { height: var(--topnav-height) }` with the 3.75rem hamburger reserve,
the `::after` rail `top` animation + `body.scrolled` scroll listener, and the
`body.*-pinned .topnav` margin pushes. `--sidebar-header-height` removed. Only the
960 breakpoint and the width model from this entry remain in force. laradcs and
sshm-desktop carry the same revert (see their journals / CLAUDE.md).

### Pin moved to the inner edge (Mark's call)
The pin and the carousel controls both crowded the outer 3.75rem next to the hamburger,
which hurt at 200px. Pinning only matters while the sidebar is visible, and what it does
is reserve space from the content — so it now sits at the inner edge (top-right corner
of the left sidebar, top-left of the right), beside the resize handle. Markup order
matches visual order (left: `.carousel-nav` then `.pin-toggle`; right: mirrored) and CSS
`margin-inline-start/end: auto` on `.pin-toggle` does the push. Spec `_spec/LAYOUT.md`
updated. Ported to laradcs the same day.

### Bug found on the way: first visit opened + pinned both sidebars, phones included
`restore()` did `s[side+'Pinned'] && desktop` → `undefined` when nothing is saved,
and `classList.toggle(name, undefined)` *toggles* instead of forcing false. Live
dcs.spa confirmed: fresh profile at 800px → `body.left-pinned.right-pinned`, both
`.open`. The desktop half of that accident is what every DCS site looked like on
first visit (and what the SPE recordings relied on), so it is now an explicit
default: **no saved key → pinned on ≥960px, closed below; saved state always wins**,
with values coerced to booleans.

### Verification (headless Chrome over CDP, fresh profiles)
- 1024×576 pinned: topnav 0–64 full width; both sidebars y=64, 200px; `main`
  margin `64px 200px 200px`, width 624; no horizontal scroll.
- 1280×800 pinned: 200px each, main 880.
- 800 fresh: closed. 1024 fresh: both pinned. 900 fresh + hamburger: left rail
  overlays at x=0, `main` unpushed, pin hidden.
- Light/forest at 1024 scrolled: topnav stays put, rails run to the bottom.
